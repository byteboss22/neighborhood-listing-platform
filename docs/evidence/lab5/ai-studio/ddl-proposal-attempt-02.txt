2. Review of First Proposal Against Attached Files & Observed 42501 Failures

A. Why the Isolated PostgreSQL Check Failed (42501 & Missing service_role Grants)
Cross-table RLS column privilege failure (42501 permission denied for table properties):

The first proposal granted anon column-level SELECT on properties and sponsors without status.

PostgreSQL evaluates RLS policies (property_sponsors SELECT, inquiries INSERT) using the invoking role's (anon) column privileges. Because both cross-table EXISTS (...) predicates read properties.status (and sponsors.status / sponsors.is_active), PostgreSQL rejected both queries with 42501 before row filtering could run.

Compare with the midterm migration (20261029140000_exam_services_persistence_692351ea.sql, lines 62–63), which explicitly included status in anon's GRANT SELECT (..., status, created_at) ON public.services TO anon.

Fix: Include status in anon's column GRANT SELECT on properties and sponsors (while still withholding owner_id, approved_at, approved_by, and updated_at), or use a SECURITY DEFINER predicate helper (labeled as Alternative B below) if status must stay hidden from anon column grants. Because RLS restricts anon rows to status = 'approved' (and is_active = true on sponsors), exposing status on returned rows reveals no unapproved state.

Missing service_role grants on clean bootstrap:

The first proposal ran REVOKE ALL ... FROM PUBLIC, anon, authenticated without adding GRANT ALL ... TO service_role (present in the midterm migration at lines 72–73). In a clean PostgreSQL bootstrap, service_role lacked SELECT/INSERT/UPDATE/DELETE on the four new tables.

Fix: Explicitly add GRANT ALL ON public.properties, public.sponsors, public.property_sponsors, public.inquiries TO service_role; (plus GRANT USAGE ON SCHEMA public TO anon, authenticated, service_role;, idempotent with the midterm migration).

CREATE OR REPLACE FUNCTION public.lab5_set_timestamps()
RETURNS trigger
LANGUAGE plpgsql
SET search_path = pg_catalog, public
AS $$
BEGIN
  IF TG_OP = 'INSERT' THEN
    NEW.created_at := COALESCE(NEW.created_at, timezone('utc'::text, clock_timestamp()));
    NEW.updated_at := timezone('utc'::text, clock_timestamp());
  ELSIF TG_OP = 'UPDATE' THEN
    NEW.created_at := OLD.created_at;
    NEW.updated_at := timezone('utc'::text, clock_timestamp());
  END IF;
  RETURN NEW;
END;
$$;

CREATE OR REPLACE FUNCTION public.lab5_enforce_property_invariants()
RETURNS trigger
LANGUAGE plpgsql
SET search_path = pg_catalog, public
AS $$
DECLARE
  jwt_role text := NULLIF(current_setting('request.jwt.claim.role', true), '');
  is_client_role boolean := (current_user IN ('anon', 'authenticated') OR jwt_role IN ('anon', 'authenticated'));
  distinct_amenities integer;
BEGIN
  -- Reject duplicate amenities (matches listing.ts validateListingBundle uniqueness)
  SELECT pg_catalog.count(DISTINCT a)
    INTO distinct_amenities
    FROM pg_catalog.unnest(NEW.amenities) AS a;

  IF distinct_amenities <> pg_catalog.cardinality(NEW.amenities) THEN
    RAISE EXCEPTION 'Duplicate values in amenities are not allowed.' USING ERRCODE = '23514';
  END IF;

  IF is_client_role THEN
    IF TG_OP = 'INSERT' THEN
      IF NEW.status NOT IN ('draft', 'pending') THEN
        RAISE EXCEPTION 'Clients may only create draft or pending properties.' USING ERRCODE = '42501';
      END IF;
      IF NEW.approved_at IS NOT NULL OR NEW.approved_by IS NOT NULL THEN
        RAISE EXCEPTION 'Clients cannot set approval metadata.' USING ERRCODE = '42501';
      END IF;
    ELSIF TG_OP = 'UPDATE' THEN
      IF NEW.owner_id IS DISTINCT FROM OLD.owner_id THEN
        RAISE EXCEPTION 'Ownership transfer is not permitted.' USING ERRCODE = '42501';
      END IF;
      IF OLD.status NOT IN ('draft', 'pending') THEN
        RAISE EXCEPTION 'Approved or suspended properties cannot be modified by owners.' USING ERRCODE = '42501';
      END IF;
      IF NEW.status NOT IN ('draft', 'pending') THEN
        RAISE EXCEPTION 'Owners cannot approve or suspend properties.' USING ERRCODE = '42501';
      END IF;
      IF NEW.approved_at IS DISTINCT FROM OLD.approved_at
         OR NEW.approved_by IS DISTINCT FROM OLD.approved_by THEN
        RAISE EXCEPTION 'Approval metadata is server-managed.' USING ERRCODE = '42501';
      END IF;
    END IF;
  END IF;

  RETURN NEW;
END;
$$;

CREATE OR REPLACE FUNCTION public.lab5_enforce_sponsor_invariants()
RETURNS trigger
LANGUAGE plpgsql
SET search_path = pg_catalog, public
AS $$
DECLARE
  jwt_role text := NULLIF(current_setting('request.jwt.claim.role', true), '');
  is_client_role boolean := (current_user IN ('anon', 'authenticated') OR jwt_role IN ('anon', 'authenticated'));
BEGIN
  IF is_client_role THEN
    IF TG_OP = 'INSERT' THEN
      IF NEW.status NOT IN ('draft', 'pending') OR NEW.is_active IS DISTINCT FROM false THEN
        RAISE EXCEPTION 'Clients may only create unapproved inactive sponsors.' USING ERRCODE = '42501';
      END IF;
      IF NEW.approved_at IS NOT NULL OR NEW.approved_by IS NOT NULL THEN
        RAISE EXCEPTION 'Clients cannot set approval metadata.' USING ERRCODE = '42501';
      END IF;
    ELSIF TG_OP = 'UPDATE' THEN
      IF NEW.owner_id IS DISTINCT FROM OLD.owner_id THEN
        RAISE EXCEPTION 'Ownership transfer is not permitted.' USING ERRCODE = '42501';
      END IF;
      IF OLD.status NOT IN ('draft', 'pending') THEN
        RAISE EXCEPTION 'Approved or suspended sponsors cannot be modified by owners.' USING ERRCODE = '42501';
      END IF;
      IF NEW.status NOT IN ('draft', 'pending') OR NEW.is_active IS DISTINCT FROM false THEN
        RAISE EXCEPTION 'Owners cannot approve, suspend, or activate sponsors.' USING ERRCODE = '42501';
      END IF;
      IF NEW.approved_at IS DISTINCT FROM OLD.approved_at
         OR NEW.approved_by IS DISTINCT FROM OLD.approved_by THEN
        RAISE EXCEPTION 'Approval metadata is server-managed.' USING ERRCODE = '42501';
      END IF;
    END IF;
  END IF;

  RETURN NEW;
END;
$$;

CREATE TABLE public.properties (
  property_id text PRIMARY KEY,
  owner_id uuid NOT NULL REFERENCES public.profiles(id) ON DELETE RESTRICT,

  zip_code text NOT NULL,

  property_type text NOT NULL,

  updated_at timestamptz NOT NULL DEFAULT timezone('utc'::text, now()),

  CONSTRAINT properties_id_format CHECK (property_id ~ '^[a-z0-9]+(?:-[a-z0-9]+)*$' AND char_length(property_id) >= 3),
  CONSTRAINT properties_title_valid CHECK (title ~ '\S' AND char_length(title) >= 5),
  CONSTRAINT properties_street_valid CHECK (street ~ '\S'),
  CONSTRAINT properties_city_valid CHECK (city ~ '\S'),
  CONSTRAINT properties_state_valid CHECK (state ~ '^[A-Z]{2}$'),
  CONSTRAINT properties_country_us CHECK (country = 'US'),
  CONSTRAINT properties_zip_valid CHECK (zip_code ~ '^[0-9]{5}(?:-[0-9]{4})?$'),
  -- Unconstrained NUMERIC scale prevents silent rounding of 12.345 -> 12.35
  CONSTRAINT properties_price_valid CHECK (price >= 0 AND price <= 99999999.99 AND price = round(price, 2)),
  CONSTRAINT properties_currency_usd CHECK (currency = 'USD'),
  CONSTRAINT properties_period_month CHECK (price_period = 'month'),
  CONSTRAINT properties_type_enum CHECK (property_type IN ('apartment', 'studio', 'house', 'condo', 'townhouse')),
  CONSTRAINT properties_bedrooms_nonnegative CHECK (bedrooms >= 0),
  -- Unconstrained NUMERIC scale prevents silent rounding of 1.54 -> 1.5
  CONSTRAINT properties_bathrooms_half_steps CHECK (bathrooms >= 0 AND bathrooms <= 99 AND (bathrooms * 2) = trunc(bathrooms * 2)),
  CONSTRAINT properties_sqft_positive CHECK (square_feet > 0),
  CONSTRAINT properties_amenities_enum CHECK (
    pg_catalog.coalesce(pg_catalog.array_ndims(amenities), 0) <= 1
    AND pg_catalog.array_position(amenities, NULL) IS NULL
    AND amenities <@ ARRAY['parking', 'laundry', 'elevator', 'balcony', 'garden', 'air_conditioning']::text[]
  ),
  CONSTRAINT properties_image_allowlist CHECK (
    image_path IN ('/images/maple-court.svg', '/images/cedar-studio.svg', '/images/willow-house.svg')
  ),
  CONSTRAINT properties_image_alt_valid CHECK (image_alt ~ '\S' AND char_length(image_alt) >= 10),
  CONSTRAINT properties_status_enum CHECK (status IN ('draft', 'pending', 'approved', 'suspended')),
  CONSTRAINT properties_approval_consistency CHECK ((status = 'approved') = (approved_at IS NOT NULL))
);

4. Change & Risk Summary
Cross-table RLS privilege alignment: Adding status to anon GRANT SELECT on properties and sponsors eliminates the 42501 permission denied for table properties error during anonymous property_sponsors SELECT and inquiries INSERT, while RLS prevents any non-approved row from being read.

Clean-bootstrap service_role grants: GRANT ALL ... TO service_role ensures service_role can read/moderate all four tables immediately after REVOKE ALL.

Contract fidelity (listing.ts): Unconstrained NUMERIC + explicit round/trunc checks prevent silent rounding of invalid values like 12.345 or 1.54; the lab5_enforce_property_invariants trigger rejects duplicate amenities.

PostgREST INSERT without RETURNING for anon: Because anon has no SELECT grant or policy on inquiries, client/API anonymous inserts must not call .select() after .insert() (matching src/app/api/bookings/route.ts).

profiles provisioning & CASCADE: owner_id references public.profiles(id) ON DELETE RESTRICT, preserving approved records. Deletion of auth.users cascades to profiles in the midterm migration and will be blocked by RESTRICT if the user owns properties/sponsors unless an explicit cleanup/offboarding policy is defined.

Direct-owner inquiries SELECT risk: Permitting owners to SELECT inquiries exposes requester_email and message to the property owner's authenticated session. If design.md intends stricter PII isolation, drop GRANT SELECT ON public.inquiries TO authenticated and inquiries_owner_read_own_property.
