3. Schema, Grant, and RLS Design Review
Keys: Surrogate uuid PKs (gen_random_uuid()) plus UNIQUE slug (slug text) on properties and sponsors; composite PK (property_id, sponsor_id) on property_sponsors prevents duplicate pairings.

Foreign Keys & Cascade Behavior:

properties.owner_id -> public.profiles(id) ON DELETE RESTRICT: avoids silent loss of moderated/historical listings if a profile deletion is attempted.

sponsors.owner_id -> public.profiles(id) ON DELETE RESTRICT: same audit/integrity protection.

property_sponsors.property_id -> public.properties(id) ON DELETE CASCADE and sponsor_id -> public.sponsors(id) ON DELETE CASCADE: join rows have no meaning independent of the parent records.

inquiries.property_id -> public.properties(id) ON DELETE RESTRICT: preserves inquiry history; since owners cannot delete approved properties, RESTRICT prevents accidental deletion.

NULLs & Checks:

NOT NULL enforced on all required Lab 3 fields, ownership FKs, statuses, and timestamps.

CHECK constraints enforce Lab 3 structural boundaries (state ~ '^[A-Z]{2}$', country = 'US', zip_code ~ '^[0-9]{5}(?:-[0-9]{4})?$', price >= 0, bedrooms >= 0, bathrooms >= 0 in 0.5 increments, square_feet > 0, controlled amenities subset via <@, allowlisted local SVGs and https://...example.(com|org|net) URLs for fictional demo safety).

Moderation consistency CHECK: (status = 'approved') = (approved_at IS NOT NULL) (and optional approved_by) prevents half-approved states.

Timestamps: created_at and updated_at (timestamptz NOT NULL DEFAULT now()) with a BEFORE UPDATE trigger (SET search_path = pg_catalog, public) that forces created_at immutable and updates updated_at.

Column Grants & Trigger Defense-in-Depth:

REVOKE ALL on all 4 tables from PUBLIC, anon, and authenticated.

anon receives SELECT on public-safe columns of properties, sponsors, and property_sponsors, plus INSERT (property_id, inquirer_name, inquirer_email, message) only on inquiries (no SELECT / RETURNING on inquiries).

authenticated receives INSERT/UPDATE only on owner-editable columns (explicitly excluding owner_id on UPDATE, status approval transitions, approved_at, approved_by, and is_active escalation).

A BEFORE INSERT OR UPDATE guard trigger rejects status = 'approved', approved_at IS NOT NULL, approved_by IS NOT NULL, or owner_id reassignment when current_user IN ('anon', 'authenticated') (so service_role retains full moderation capability).

Default-Deny RLS:

ENABLE ROW LEVEL SECURITY on all 4 tables; no FOR ALL blanket policies.

Note: Do not apply FORCE ROW LEVEL SECURITY in a way that blocks table-owner migrations or trusted service_role if running in a custom role setup; verify service_role bypasses RLS in the target Postgres/Supabase environment.

CREATE OR REPLACE FUNCTION public.lab5_set_timestamps()
RETURNS trigger
LANGUAGE plpgsql
SET search_path = pg_catalog, public
AS $$
BEGIN
  IF TG_OP = 'INSERT' THEN
    NEW.created_at := COALESCE(NEW.created_at, clock_timestamp());
    NEW.updated_at := clock_timestamp();
  ELSIF TG_OP = 'UPDATE' THEN
    NEW.created_at := OLD.created_at;
    NEW.updated_at := clock_timestamp();
  END IF;
  RETURN NEW;
END;
$$;

CREATE OR REPLACE FUNCTION public.lab5_enforce_moderation_boundary()
RETURNS trigger
LANGUAGE plpgsql
SET search_path = pg_catalog, public
AS $$
DECLARE
  jwt_role text := NULLIF(current_setting('request.jwt.claim.role', true), '');
  is_client_role boolean := (current_user IN ('anon', 'authenticated') OR jwt_role IN ('anon', 'authenticated'));
BEGIN
  IF is_client_role THEN
    IF TG_OP = 'INSERT' THEN
      IF NEW.status NOT IN ('draft', 'pending') THEN
        RAISE EXCEPTION 'Clients may only create draft or pending records.' USING ERRCODE = '42501';
      END IF;
      IF NEW.approved_at IS NOT NULL OR NEW.approved_by IS NOT NULL THEN
        RAISE EXCEPTION 'Clients cannot set approval metadata.' USING ERRCODE = '42501';
      END IF;
    ELSIF TG_OP = 'UPDATE' THEN
      IF NEW.owner_id IS DISTINCT FROM OLD.owner_id THEN
        RAISE EXCEPTION 'Ownership transfer is not permitted.' USING ERRCODE = '42501';
      END IF;
      IF OLD.status NOT IN ('draft', 'pending') THEN
        RAISE EXCEPTION 'Approved or finalized records cannot be modified by owners.' USING ERRCODE = '42501';
      END IF;
      IF NEW.status NOT IN ('draft', 'pending') THEN
        RAISE EXCEPTION 'Owners cannot approve or reject records.' USING ERRCODE = '42501';
      END IF;
      IF NEW.approved_at IS DISTINCT FROM OLD.approved_at
         OR NEW.approved_by IS DISTINCT FROM OLD.approved_by THEN
        RAISE EXCEPTION 'Approval metadata is server-managed.' USING ERRCODE = '42501';
      END IF;
    END IF;
  END IF;
  RETURN NEW;
END;
$$;

5. Key Risks & Mitigations
PostgREST INSERT ... RETURNING trap on inquiries:

Because anon and authenticated have no SELECT grant or policy on inquiries, calling .insert(data).select() from Supabase JS will fail with 42501. Application routes must insert without .select() (mirroring src/app/api/bookings/route.ts).

Missing profiles row at signup:

owner_id REFERENCES public.profiles(id) fails if a newly authenticated user does not yet have a profiles row. Verify how the midterm migration provisions profiles before letting owners submit listings.

Sponsor deactivation vs. unapproved edit rule:

sponsors_active_requires_approved ensures unapproved sponsors always have is_active = false. Only service_role moderation can set status = 'approved' and is_active = true together. If owners need to pause an already-approved sponsor, that must be handled via an explicit server-side endpoint or narrowed column/trigger exception.

Existence probing on inquiries / property_sponsors:

Attempting to insert an inquiry against a draft property UUID fails RLS (42501), whereas a nonexistent UUID fails FK (23503). Public API routes should map both to a uniform 400 { error: "Property is unavailable." } response.

service_role key leakage:

service_role bypasses RLS. Never instantiate it in client bundles, Server Components rendered for owners, or owner edit routes; restrict it strictly to server-only moderation scripts/admin operations.

Constraint drift with Lab 3:

The properties_amenities_enum and properties_image_allowlist checks mirror schemas/listing-bundle.schema.json. Keep Zod (src/schemas/listing.ts) and Postgres CHECK constraints synchronized when new amenities or assets are introduced.
